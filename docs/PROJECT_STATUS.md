# Lorethra project status and prioritized backlog

**Status date:** 2026-10-30
**Current schema:** v17
**Project state:** implementation in progress; not a release approval.
**Status meanings:** Complete means the scoped behavior has implementation and acceptance evidence. Partial means useful source behavior exists but required acceptance remains open. Open means the backlog outcome is not yet implemented or verified. Deferred means it is outside the current single-user local-first release boundary.

## Product outcome

Deliver a local-first platform for creating reusable worlds, building protagonists, and playing persistent, isolated adventures with independent characters, flexible deterministic mechanics, reviewed continuity, portable packages, recovery, and a usable Windows desktop application. SQLite remains canonical; providers, projections, imports, and generated narrative never gain direct write authority.

## Current implementation slice

- World-pinned character point-buy, exceptional abilities, and configurable deterministic mechanics are implemented. Gateway validation uses the immutable world version pinned by each adventure.
- Adventure turn editing supersedes downstream history from canonical order and reconstructs supported RPG sheet, NPC profile, and map state while preserving direct player edits.
- World and adventure packages have checksum manifests, validated legacy upcasts, decoded asset checks, import previews, and reviewable export modes. MNO world v1 and adventure v2 conversion is available.
- External provider requests require matching consent and filter private context. Cancellation reaches local, hosted HTTP, and Codex adapters, with no partial turn commit on tested cancellation paths.
- World and adventure libraries include search, filters, sorting, rename/status controls, duplication, archive/restore, and a collapsed maintenance menu. Story Studio now places **New adventure** beside the resume-first list, removes the duplicate newest-adventure card, previews eight additional matches before disclosure, and names setup steps for their actual tasks. The 32-adventure browser review verified setup entry, expansion, and search/count behavior; broader lifecycle and accessibility acceptance remains open.
- World creation now has an optional local-only World Architect. Ollama returns a structured, semantically checked draft; the user can cancel generation, review and explicitly apply a draft to editable fields, then save it through the command gateway. Manual creation remains available when Ollama is unavailable or drafting is canceled. Focused gateway/API/browser and model-quality acceptance has not yet been run.
- World authoring now follows three short steps: setting, places/opening, and optional rules/review. Field-level location and opening-scene checks block progression until valid; advanced mechanics stay collapsed by default, and returning to earlier steps preserves the draft. The final save still uses the canonical gateway. Focused browser, keyboard, and narrow-window acceptance remains open.
- World versions can include an optional structured public opening scene. The author can enter its situation and immediate hook, review it before starting an adventure, and later revise it as a new immutable world version. It is included in the first story-generation context only and remains subject to player agency and provider-consent rules. Package/API/browser acceptance for this addition has not yet been run.
- Reusable heroes can carry optional concept, background, personality, goal, and voice notes. The guided setup can create or edit these notes, reviews them before play, saves them through the gateway, and excludes them from hosted-provider requests. Active adventures can edit their own actor snapshot, including imported MNO details, without changing the reusable main-branch hero or sibling adventures. Historical retries retain the saved profile snapshot. Focused profile package/privacy and browser acceptance remains open.
- See CHANGELOG.md for the full feature-by-feature record in this PR. See docs/ACCEPTANCE_MATRIX.md for test and release evidence.

## UX research and applied principles

Reviewed on 2026-10-29. The linked articles consistently recommend showing the user's primary task first, grouping related information, using progressive disclosure for less frequent controls, giving clear feedback and empty states, preserving consistent navigation, and adapting to narrow windows and accessibility needs.

Applied to Story Studio: keep search and the most likely next actions visible; place optional filters under “Filters & sort”; keep resume/start actions on the card and move maintenance actions under “More”; report result counts and provide a clear reset when nothing matches; preview a manageable number of results and disclose the rest; use short guided setup steps named for their actual task; make point-budget rules explicit; retain focus visibility, labels, and responsive layouts. World authoring now separates setting, places/opening, and optional rules/review, with field feedback before save and a preserved draft when navigating back. The browser check verified the create entry, list disclosure, and full-library search/count on 32 adventures; the new world-authoring wizard, keyboard/screen-reader, and other viewport checks remain subject to the acceptance matrix.

Sources reviewed: [UX Pilot](https://uxpilot.ai/blogs/dashboard-design-principles), [UXPin](https://www.uxpin.com/studio/blog/dashboard-design-principles/), [RIB Software](https://www.rib-software.com/en/blogs/bi-dashboard-design-principles-best-practices), [GammaUX](https://www.gammaux.com/en/blog/6-ux-principles-for-effective-dashboard-design/), [AllCloneScript](https://medium.com/@allclonescript/20-best-dashboard-ui-ux-design-principles-you-need-in-2025-30b661f2f795), [Context.dev](https://www.context.dev/blog/dashboard-design-best-practices), [UX Collective](https://uxdesign.cc/58-rules-for-stunning-and-effective-user-interface-design-ea4b93f931f6), [Maze](https://maze.co/collections/ux-ui-design/ui-design-principles/), [Figma](https://www.figma.com/resource-library/ui-design-principles/), and [Multitude IT Labs](https://medium.com/multitude-it-labs/basic-ui-rules-every-front-end-developer-should-know-e4eff8ad0dbc).

## Delivery order

1. Close integrity, privacy, migration, and recovery gaps; rebuild and verify the current Windows package.
2. Complete the create/import → protagonist review → isolated adventure → resume lifecycle, including searchable libraries and clear failure/recovery paths.
3. Improve semantic memory correction, NPC identity/knowledge scoping, and broader reconstruction after historical edits.
4. Measure narrative quality and bilingual retrieval on a fixed corpus before expanding simulation.
5. Add authoring, image, and publishing depth after the local text and recovery workflows are proven.
