# Data Model Contract

The canonical model is general-purpose. `canon` is a story-specific authority concept; it is not a universal synonym for truth.

## Core records

| Record | Meaning | Authority and ownership |
|---|---|---|
| Workspace | Independent data, settings, and access boundary | User-owned |
| Source / SourceVersion | Original file or text and immutable content version | Source manager |
| Evidence | Recoverable source excerpt or explicit user record | Source-linked, revisioned |
| Entity / Alias | Stable identity and alternate names | Knowledge core |
| Claim | Subject-predicate-object assertion | Keeps evidence, epistemic state, and review state separate |
| Relation | Typed, directed link between entities | Branch-scoped; reviewable |
| Event / State | Occurrence and computed state at a domain time | Time and evidence required as available |
| JournalEventVersion | A user's account of an episode, with optional source, participants, and exact, ranged, relative, or unknown timing | Branch-scoped, provenance-preserving, append-only corrections; not independently verified truth |
| Belief / Knowledge | What an actor knows, believes, denies, or lacks | Actor- and awareness-order-scoped |
| Rule | Constraint on a subject, predicate, and value | Branch-scoped, reviewed, hard or soft; evaluator reports satisfied, violated, or unknown |
| Revision / Branch | Versioned change and isolated alternate path | Append-only history; explicit promotion |
| Conversation / Turn | Lorethra story exchange and ordering | Branch-scoped; local generation provenance |
| StoryWorld / WorldVersion | Reusable world identity and immutable, reviewed setting snapshot | Workspace-scoped; new edits append a version |
| StoryAdventure | Named play session pinned to one world version and one branch snapshot | Branch-scoped; sessions from one world remain isolated |
| RPGSheet / Check | Character stats, world-specific skills and experience, bounded trackers, location, and immutable check records | Adventure-branch scoped; mechanics resolve against the pinned world version |
| StoryAbility / AbilityState | Explicit ability definition pinned to an immutable world version and adventure-branch activation/cooldown state | Abilities are separate from stats and trackers; only declared costs and cooldowns constrain activation |
| RPGStateProposal | Suggested tracker or location change linked to an optional assistant turn | Branch-scoped; pending until a human accepts or rejects it |
| ExternalExchange | Untrusted imported transcript segment, context manifest, turn range, and proposal references | Immutable, branch-scoped archive; deduplicated and continuity-checked by transcript ID |
| Scenario | Options, constraints, assumptions, and conditional outcomes | Separate from baseline truth |
| StyleProfile | Descriptive or user-preferred narrative traits | Provenance and confidence required |
| Job / Approval | Processing, permission, review, and result | Auditable; scoped authority |

Review status (`proposed`, `accepted`, `rejected`) is distinct from epistemic status (`unknown`, `believed`, `known`, `contested`). A proposal can be accepted for recording while the proposition remains uncertain. Conflicting accounts remain independently addressable with provenance.

## Time

Records may carry valid time, recorded time, actor awareness time, narrative order, and branch revision. Time values may be exact, relative, interval-valued, or unknown. A correction changes the account from its recorded point; a retcon revises world truth and must create a new revision while preserving the prior state.

## Branches and identity

Stable entity IDs are scoped to a workspace and branch snapshot. Creating a branch snapshots records from an exact parent revision. Subsequent writes remain branch-local. A source archive is shared within a workspace; its evidence links and accepted knowledge are branch-aware. Promotion is an explicit, human-reviewed fast-forward into the direct parent, allowed only while the parent remains at the exact source revision and the child head matches the reviewed head. One parent revision records the promotion; child history remains intact and identifies the provenance for the promoted state. A stale parent or stale reviewed head is rejected without a merge. Automatic conflicting merges are out of scope for v0.1.

## SQLite v17 implementation

The current schema provides workspaces, branches, revisions, commands, entities, relations, claims, rules, actor beliefs, sources, evidence, journal records, scenarios, extraction records, story conversations and turns, world versions, adventures, RPG sheets/checks/proposals, memories, threads, NPC profiles, assets, map locations, audit history and projection outbox, plus FTS5 entity/source indexes. Story turns carry provider/model provenance, narrative order, an optional context manifest and revision, MNO source-role metadata, and immutable edit history. Adventures may retain an immutable `.mno-adv` source archive; it is a recovery/export artifact and never generation context. RPG sheets and map points carry optional region and coordinates. Adventure branches snapshot their scoped story records and RPG state. Journal entries preserve source quotes, participant labels, and exact, ranged, relative, or unknown timing. A correction appends a version; earlier wording and conflicting accounts remain retrievable. Claims and awareness records use relative narrative order to prevent future-knowledge leakage.

World versions, including their names, descriptions, templates, lore, optional point-buy rules, and optional exceptional-ability definitions, and d20 results are append-only. An adventure references one immutable world version and a direct-child workspace snapshot; later world edits do not alter its pinned version or displayed world name. Its RPG sheet, checks, ability activation states, story turns, and state proposals follow the adventure branch and are copied when that branch is forked. The built-in d20 check records the user-facing die, current stat modifier, total, target, and outcome in one gateway command. Current reviewed state proposals support bounded tracker changes and setting the current location; acceptance is human-only, requires the current branch revision, and fails if the sheet changed after the proposal. Rejected and pending changes do not modify the sheet.

Schema v15 stores adventure ability activation state separately from stats and trackers. Immutable world-version definitions describe activation and deactivation, effects, declared costs and cooldowns, duration, range, interaction with ordinary magic, demonstrated capabilities, confirmed limitations, and unresolved aspects. The gateway enforces only a declared resource cost and completed-turn cooldown; absent costs or cooldowns impose no restriction. It does not infer mana use, d20 checks, levels, or other mechanics. Definitions and active state survive world/adventure package export/import, branch snapshots, and revision-based RPG-state reconstruction. The model receives these constraints in story context so prose cannot silently weaken a demonstrated ability or invent restrictions.

Schema v16 adds branch-local skill ranks, persistent manual experience awards, and immutable configured-mechanics check records. Each immutable world version may define d20, custom dice (sum, highest, or success-count), narrative-only or hybrid resolution, bounded difficulty targets, encounter types, skill attributes/bonuses/rank limits, and manual, automatic, or hybrid experience. Adventures copy starting skills and XP state and remain pinned to that profile after later world revisions. The API generates dice within the configured range; the gateway validates the submitted rolls and resolves all arithmetic from the pinned rules and current sheet. Automatic XP derives from completed player turns, while manual awards require player review and obey the pinned cap. Check snapshots retain the exact rules used; package import, branch snapshots, history reconstruction, and backup/restore preserve skills, XP and checks.

Schema v17 adds nullable archive timestamps to worlds and adventures and indexes for active/archive library queries. Archived records remain in canonical history and can be restored; an archived world cannot be used to start a new adventure. Library state changes are revisioned commands. World cover images are optional, validated local image data pinned to an immutable world version; they are not remote URLs.

Extraction batches record the immutable source digest, local model, extractor/prompt versions, and output schema version. Entity and claim candidate payloads are immutable and retain an exact source quote plus character offsets. Candidate review status and any created canonical record are stored separately. AI-originated batches cannot review themselves; a user acceptance command creates the entity/claim and its evidence atomically. These records are branch-scoped while their original source remains workspace-scoped.

The rule evaluator supports one reviewed require/forbid condition per rule. It uses accepted public claims marked known, respects an explicitly declared single-valued predicate, and keeps missing, private, unreviewed, uncertain, or conflicting evidence unknown. Each scenario records its problem, constraints, two or three options, and links to branch claims or workspace sources. Assumptions are stored separately from claims as append-only versions; proposals are excluded until accepted. A `replace` assumption overlays a single-valued property for one option, while `add` overlays a value on a multi-valued property. Each option receives deterministic rule outcomes marked as baseline or conditional, with claim and assumption references kept distinct. These checks do not score outcomes or generate model recommendations. Scenario records and assumptions are immutable and branch-scoped. Journal event accounts are manually recorded and remain personal accounts even when linked to a source. They are not yet extracted into general domain events, linked to canonical entity identities, or used for temporal question answering. Story v15 stores turn source roles, immutable MNO adventure source archives, map coordinates, and adventure-local ability states; schema v16 adds branch-local mechanics progression; schema v17 adds world/adventure archive state. The current package adapters accept `.lke-world`, `.lke-adventure`, MNO `.mno-world` v1 and `.mno-adv` v2. Semantic event extraction and correction links, authored map editing, live-provider verification, and release packaging remain incomplete. Searchable/filterable/sortable libraries and lifecycle actions exist, but browser and installed-desktop acceptance remain partial.

`promote_branch` carries a reviewed child snapshot into its unchanged direct parent. Existing mutable entity, relation, claim, rule, conversation, and extraction-review state is applied to matching records; branch-local records are inserted in foreign-key dependency order. Append-only journal events, scenarios, options, evidence links, assumptions, extraction batches, and candidate payloads are preserved without updating or deleting parent history. New or updated branch revision markers point to the parent's single promotion revision, while the source branch and its full command history remain available as provenance. Entity search is rebuilt from the promoted parent state. Promotion does not convert scenario assumptions into claims, and it does not merge concurrent parent edits.
