# Research and specification workflow

1. State the user outcome and scope; inspect the current product definition and relevant source.
2. Read official product pages and detail documentation. For interactive products, inspect low-impact navigation and settings without creating accounts, sessions, paid generations, uploads or lasting test data unless the user explicitly authorized that testing. Record inspection date, observed controls, advertised behavior and blocked access separately. Do not upload project data to test an external tool.
3. For each opportunity list existing foundation, precise gap, user benefit, source, confidence, cost/complexity and architectural fit.
4. Specify the journey from entry through review and persistence to reopen/export. Include cancellation, stale revisions, duplicates, invalid import, provider failure and empty state. Record whether state is stored locally, remotely or in both places, and how backup, identity recovery and deletion behave.
5. Define proposed ownership, commands, records, projections, permission checks and migration/recovery effects in prose. Keep proposals separate from established contracts.
6. Write observable acceptance criteria and dependencies. Prioritize continuity and integrity before media breadth. Update the plan's evidence limits honestly.

Evidence entry fields: ID; URL or repository path; inspected date; supported observation; advertised versus observed versus tested; local counterpart; gap; uncertainty; recommended next proof. No fabricated scores or timelines.
